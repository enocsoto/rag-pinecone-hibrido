# Chunking con RecursiveCharacterTextSplitter

Subir el archivo entero como un solo vector diluye el embedding: la pregunta habla de un párrafo y el vector representa veinte temas a la vez. Cortar en frases sueltas pierde el sujeto de la oración anterior. El punto medio para documentación técnica está entre 500 y 800 tokens. RecursiveCharacterTextSplitter mide en caracteres, así que un chunk_size de 2400 caracteres, con overlap de 300, cae en esa franja. Cuatro caracteres aproximan un token en español técnico, con variación según el vocabulario.

El splitter es recursivo porque prueba separadores de mayor a menor: doble salto de línea, salto simple, espacio y, al final, el corte por carácter. Así intenta no partir una sección a la mitad. El overlap repite el final del chunk anterior al inicio del siguiente para que una definición que cae en el borde siga presente en los dos vectores.

Cada chunk hereda la metadata del documento y suma page con el índice del fragmento, empezando en 0. El id del vector concatena el doc_id y ese page. Si se cambia chunk_size hay que reingestar: los ids viejos quedan apuntando a recortes que ya no existen. Borrar el namespace antes de una reingesta evita mezclar las dos generaciones.

Chunks demasiado chicos, de menos de cien tokens, hacen que la búsqueda devuelva una frase sin el ejemplo que la explica. Chunks de varios miles de tokens hacen que Precision@k baje, porque el texto recuperado contiene el dato pedido y también tres temas vecinos que no sirven para responder. 2400 caracteres es el compromiso que usa este pipeline.

Los separadores, en orden, son el doble salto de línea, el salto simple, el espacio y el carácter. Un título de markdown y el párrafo que le sigue suelen quedar juntos si entran en 2400 caracteres. El overlap de 300 caracteres repite el cierre de la sección anterior. Ese repetido no es un documento nuevo: comparte source con el chunk previo y solo cambia page. La evaluación trata como útil cualquier chunk cuyo source sea el archivo esperado, así que dos chunks del mismo markdown cuentan los dos para Precision@5. El doc_id es el nombre del archivo sin extensión. page empieza en cero para el primer recorte de ese archivo. Si un markdown queda por debajo de 2400 caracteres, el splitter devuelve un solo chunk y page queda en 0. No es un error: el tamaño manda, no una cuota de fragmentos. Cuando el archivo crece, la misma función parte en dos y el segundo recibe page 1, con 300 caracteres repetidos del cierre anterior.
