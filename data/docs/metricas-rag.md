# Precision@k y Recall@k en un golden set

Un golden set es una lista corta de preguntas cuyo documento fuente ya se conoce. Cada ítem tiene pregunta y documento_id_esperado. No hace falta una respuesta redactada: la evaluación mira si el recuperador trajo el archivo correcto, no si un modelo generó una frase bonita.

Recall@5 pregunta si el documento correcto está entre los 5 recuperados. Si está, el recall de esa pregunta es 1. Si no está, es 0. El recall del benchmark es el promedio de las cinco preguntas. Con un solo documento relevante por pregunta, Recall@k no puede valer 0.5 en una pregunta individual: o apareció o no apareció.

Precision@5 pregunta qué porcentaje de esos 5 resultados son útiles. Acá un resultado es útil cuando su metadata source es el documento esperado. Si 2 de los 5 chunks salen de ese archivo, la precisión de la pregunta es 0.4. Si los 5 salen de otros archivos, la precisión es 0. Traer el documento correcto una sola vez y llenar el resto con ruido deja el recall en 1 y la precisión en 0.2. Las dos métricas no miden lo mismo: recall perdona el ruido, precisión lo cobra.

El script evaluate.py imprime cada pregunta, los source del top 5, y al final el promedio de Recall@5 y de Precision@5. El golden set de este repo tiene cinco preguntas, una por archivo de data/docs. Si se agrega un documento, hay que agregar una pregunta que solo ese archivo pueda responder. Si no, el promedio mezcla aciertos fáciles con preguntas que no tienen fuente.

El archivo data/golden_set.json guarda pregunta y documento_id_esperado. El id esperado es el nombre del markdown, por ejemplo metricas-rag.md. No es el id del chunk. Una pregunta se considera recuperada cuando alguno de los cinco source coincide con ese nombre. Precision@5 divide la cantidad de coincidencias por 5, no por la cantidad de chunks que existan del archivo. Si el recuperador devuelve menos de 5, los faltantes no se inventan: el denominador sigue siendo 5, así que un top corto baja la precisión. Recall@5 no se divide por 5. Con una sola fuente relevante, verla una vez alcanza para el 1 de esa pregunta. El promedio de las cinco preguntas es el número que resume el benchmark. Una corrida sin API no puede calcular ese promedio: evaluate.py abre Pinecone y OpenAI. La aritmética de las métricas sí se prueba sola, con tests/test_metrics.py, sin red. Ahí se fija que un acierto en la posición 2 sigue contando para Recall@5 y que dos chunks útiles sobre cinco dan precisión 0.4.
